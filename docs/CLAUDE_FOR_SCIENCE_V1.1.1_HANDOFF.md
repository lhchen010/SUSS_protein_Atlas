# SUSS Protein Atlas v1.1.1: FoldTree Rooting Recovery

## Purpose

This patch addresses the FoldTree failure observed for three-member families F53 and F58 in
run `20260723-003323-cor-7a72a790`. In both cases, FoldTree produced a valid pre-root Newick tree,
but MAD produced an empty `.rooted` file and `process_madroot.py` then failed while parsing it.

The patch is implemented in the SUSS wrapper so deployments remain protected even when the
installed FoldTree package has not yet changed.

## Behavioral changes

1. FoldTree metrics are recovered independently. Failure of one MAD-rooting target does not
   discard valid trees from the other metrics.
2. Families with three members use midpoint rooting directly. FoldTree still computes each
   pre-root structural tree; only the rooting step changes.
3. Families with four or more members use this explicit priority:
   `MAD .rooted.final` → valid raw MAD `.rooted` → midpoint-rooted valid `.PP.nwk`.
4. Every published tree is parsed and checked for:
   nonempty Newick, a terminator, exact family leaf membership, unique leaf names, and finite
   non-negative branch lengths. Zero-length branches remain valid.
5. Tree output is written atomically, preventing interrupted jobs from publishing partial files.
6. FoldTree logs are appended by attempt instead of overwritten.
7. Each family now has `<family>_foldtree_status.json`, containing the method, source stage,
   recovery reason, nested return code, and per-metric status.
8. The atlas tree panel and downloadable workbook report the actual rooting method instead of
   always claiming MAD rooting.

## Scientific interpretation

Midpoint fallback changes the placement of the root, not the unrooted topology generated by
FoldTree. The fallback is never silent: its method and reason are included in JSON, the atlas,
and the family Excel workbook. SUSS does not fabricate a star tree or accept a tree with missing
family members.

## Residual risk

The observed association between three-member trees, zero-length branches, and MAD's empty output
is based on F53 and F58; it is not treated as a universal FoldTree theorem. The implementation
therefore validates all outputs and applies the policy by family size rather than checking only
for zero-length branches.
